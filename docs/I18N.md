# Internationalization (i18n) Architecture & Guide

> **Version:** 2.2.0  
> **Status:** Production Standard  
> **Supported Locales:** Español (`es`, Default) & English (`en`)

---

## 🌐 1. Architectural Overview

Codex Config Manager v2.2.0 features a zero-dependency, single-file internationalization engine embedded directly into `src/web/index.html`. It delivers instant, in-place language switching between Spanish and English without page reloads, external runtime frameworks (no React, Vue, or i18next), or build bundlers.

```
┌────────────────────────────────────────────────────────────────────────┐
│                        DESKTOP UI (Bilingual)                          │
│                                                                        │
│   [ES | EN] ──► setLanguage(lang) ──► localStorage                     │
│                       │                                                │
│                       ├─► document.documentElement.lang                │
│                       ├─► applyStaticTranslations() [data-i18n*]       │
│                       ├─► Dynamic Adapters (Hero, Accounts, Pipeline)  │
│                       └─► Intl.DateTimeFormat (es-CO / en-US)          │
└────────────────────────────────────────────────────────────────────────┘
```

### Key Highlights
- **Strict Default:** Defaults to Spanish (`es`) on first load. Does not guess or infer from the browser's operating system language to guarantee a predictable user baseline.
- **Persistence:** Remembers user preference in `localStorage` under `codex-config-manager:ui-language` with graceful fallback to `es`.
- **Instant In-Place Switching:** Zero network latency, zero screen flicker, zero state loss. Form values, search queries, active tabs, dirty state (`isDirty`), and open modals remain intact across language toggles.
- **Purely Presentational:** The i18n layer never mutates `config.toml`, SQLite thread entries, or process execution parameters.

## 🔒 2. Strict Invariants

When localizing or extending strings, the following system invariants are preserved:

1. **Codex Permissions Invariant:**
   - Values of `sandbox_mode`, `approval_policy`, `approvals_reviewer`, and `windows.sandbox` are machine constants.
   - Only explanatory label descriptions and help text translate.
2. **Reasoning Engine Invariant:**
   - All 7 reasoning effort levels (`none`, `low`, `medium`, `high`, `xhigh`, `max`, `ultra`) remain unchanged.
   - OmniRoute combo routing determines effective effort.
3. **TOML Round-Trip Invariant:**
   - Raw configuration keys and comments in disk TOML are never localized or altered.

## 🛠️ 4. Developer Usage

### Static DOM Translation (`data-i18n*`)
Annotate HTML elements using declarative attributes:

```html
<!-- Text Content -->
<span data-i18n="nav.accounts">MONITOR CUENTAS</span>

<!-- Title Tooltip -->
<button data-i18n-title="header.btn_diff_title" title="...">
  <span data-i18n="header.btn_diff">VER DIFF</span>
</button>

<!-- Input Placeholder -->
<input data-i18n-placeholder="features.search_placeholder" placeholder="...">

<!-- Accessibility Label -->
<div role="group" data-i18n-aria-label="a11y.lang_selector" aria-label="...">
```

### Dynamic String Translation (`t`)
In client-side JavaScript, use the `t(key, params)` helper:

```javascript
// Basic translation
const label = t('common.save_changes');

// Parameterized interpolation
const msg = t('telemetry.accounts_ready', { ready: 3, total: 5 });
// ES: "CUENTAS: 3/5 LISTAS"
// EN: "ACCOUNTS: 3/5 READY"
```

### Resilient Date/Time Formatting
Use the standard formatting helpers which automatically adapt to the active locale (`es-CO` vs `en-US`):

```javascript
formatTime(timestamp);     // e.g. "15:30:00" or "03:30:00 PM"
formatDate(timestamp);     // e.g. "18/10/2026" or "10/18/2026"
formatDateTime(timestamp); // Localized date and time

// Null, undefined, or invalid timestamps safely resolve to "N/A"
formatTime(null);          // "N/A" (never "Invalid Date")
```

## 🧪 5. Automated Verification Gates

Every translation key is verified through two automated testing gates:

1. **Static Quality & Symmetry Suite (`tests/i18n-static.test.mjs`):**
   - Asserts exact 1:1 key parity between `es` and `en` (zero missing keys).
   - Validates that all placeholder parameters `{param}` match across languages.
   - Ensures all `data-i18n*` attributes found in `src/web/index.html` exist in `MESSAGES`.
   - Checks fallback behavior for unsupported locales.
2. **Playwright Bilingual E2E Suite (`tests/e2e-i18n.test.mjs`):**
   - Verifies default Spanish on initial load.
   - Tests in-place switching to English and back to Spanish without page reloads.
   - Asserts persistence across browser restarts and `localStorage` syncing.
   - Proves state preservation (inputs, active filters, dirty state, open modals).
   - Validates keyboard navigation (`Enter` / `Space` on language toggle).

```powershell
# Run i18n tests specifically
npm run test:i18n

# Run all 6 test suites
npm test
```
